# Frontend Architecture

> **Last updated:** 2026-10-21
> **Main stack:** Next.js 13.4 (App Router) · React 18 · TypeScript (strict) · Tailwind CSS + shadcn/ui (Radix) · TanStack React Query v4 (server state) · Zustand v4 (client state) · react-hook-form + Zod (forms) · Axios (HTTP) · pnpm

Internal admin dashboard for **Moto Candela** (branches, inventory, orders, transactions, reports, surveys, used-bike intake) plus a public landing page. Dev server runs on port **3001**.

## Reusable Components

### Design System Primitives (`src/components/ui/`)

Wrappers over Radix + `class-variance-authority`. All accept `className` merged through `cn()`.

- **`Button`** (`components/ui/button.component.tsx`)
  - **Purpose:** Base button with CVA variants.
  - **Main props:** `variant` (`default|destructive|outline|secondary|ghost|link`), `size` (`default|sm|lg|icon`), `asChild`
  - **When to reuse:** Every clickable action. Never style a raw `<button>`. ⚠️ `components/ui/button.tsx` is a near-duplicate shadcn re-add — prefer `button.component.tsx`.
- **`Input` / `Textarea` / `Label` / `Checkbox` / `Separator` / `Badge` / `Card`** (`components/ui/*.component.tsx`)
  - **Purpose:** Styled HTML/Radix primitives. `Checkbox` adds `indeterminate`; `Card` exports `CardHeader/Title/Description/Content/Footer`.
  - **When to reuse:** Any form field, chip, or panel surface.
- **`Dialog`** (`components/ui/dialog.component.tsx`)
  - **Purpose:** Radix dialog with scroll handling.
  - **Main props:** `width` (default `75%`), `maxHeight` (default `80vh`) on `DialogContent`
  - **A modal opening on top of another** stacks veils: each dialog paints its own `bg-black/80`, so the background reads darker than with a single modal. That is the intended look — see `TransactionDetailsDialog` over `OrderDetailsModal`, and (same pattern) `TransactionDetailsDialog`'s "Número de orden" link opening `TransactionOrderModal` (`components/modals/transactionOrderModal.component.tsx`) on top, which itself picks `OrderDetailsModal` or `PurchaseOrderDetailModal` depending on the order's `type`.
  - **When to reuse:** Base for every modal in `components/modals/`.
- **`AlertDialog`, `DropdownMenu`, `Popover`, `Select`, `Tabs`, `Command`, `Toast`/`Toaster`** (`components/ui/`)
  - **Purpose:** Radix/cmdk wrappers for confirmations, menus, comboboxes, tabbed views and notifications.
  - **When to reuse:** Any overlay or composite control; `Command` powers searchable selects (see `BranchSelector`, `ClientSearch`).
  - `SelectContent` caps its height with `--radix-select-content-available-height` and defaults to `collisionPadding: 8`, so a list opening upwards scrolls instead of being clipped.
- **`Form`** (`components/ui/form.component.tsx`)
  - **Purpose:** react-hook-form bridge (`Form`, `FormField`, `FormItem`, `FormLabel`, `FormControl`, `FormMessage`, `useFormField`).
  - **Main props:** `control`, `name`, `render`
  - **When to reuse:** Mandatory for every form — gives accessible ids and Zod error rendering for free.
- **`Table`** (`components/ui/table.component.tsx`)
  - **Purpose:** Styled table atoms (`TableHeader/Body/Row/Head/Cell/Footer`).
  - **When to reuse:** Building any custom table in `components/tables/`.
- **`Progress`** (`components/ui/progress.component.tsx`)
  - **Purpose:** Barra de progreso accesible (`role="progressbar"` + `aria-valuemin/max/now`), un `div` con Tailwind — **sin** `@radix-ui/react-progress`.
  - **Main props:** `value`, `max?` (default `100`; se recorta a `0..max`), `size?` (`sm|md|lg`), `tone?` (`default|amber|blue|emerald|gray`), `indicatorClassName?`, más los atributos de un `div` (pasá `aria-label` / `aria-valuetext`). El texto ("8 / 10") lo pone quien la usa.
  - **In use:** `BikeRequestProgress` y el diálogo de despacho de Solicitudes Arranca.
- **`ReportChart`** (`components/ui/reportChart.component.tsx`)
  - **Purpose:** Un gráfico de ECharts que sigue a su contenedor (`ResizeObserver`) y aplica cada `option` con `notMerge`. Movido desde `arrancaMcReport/` para compartirlo.
  - **Main props:** `option`, `height?` (280), `ariaLabel`. Importarlo con `next/dynamic` y `ssr: false`, como hacen los reportes.
  - **In use:** reporte "Arranca - MC" y Metas de ventas.
- **`MonthSelect`** (`components/ui/monthSelect.component.tsx`)
  - **Purpose:** Selector de mes (`YYYY-MM`) del más reciente al más antiguo, en Caracas, con etiquetas "Octubre 2026".
  - **Main props:** `value`, `onValueChange`, `pastMonths?` (12), `futureMonths?` (1), `disabled?`, `className?`. El mismo archivo exporta `currentMonthInCaracas()`, `monthLabel()` y `shiftMonth()`.
- **`useToast` / `Toaster`** (`components/ui/use-toast.ts`, `toaster.tsx`)
  - **Purpose:** Imperative toast API (`toast({ title, description, variant })`).
  - **When to reuse:** All success/error user feedback.

### Generic Composite Components

- **`GenericTable`** (`components/tables/genericTable.component.tsx`) — **the default table of the project**
  - **Purpose:** Minimal, modern table shell: light-grey uppercase **sticky** header, zebra rows (`bg-gray-50` on odd rows, lighter than the header on purpose), hover highlight, clickable cells, an "Acciones" column, loading skeleton, empty state and optional pagination.
  - **RULE — always use it, never clone it:** every new table must be built with `GenericTable`. If a table needs behaviour that does not exist here yet (sorting, selection checkboxes, expandable rows, column groups, totals footer…), **extend this component with a new prop or variant and document it here** — do not write another table component. The existing per-domain tables in `components/tables/` predate it and are migrated opportunistically.
  - **Main props:**
    - `columns: GenericTableColumn<T>[]` — `{ key, header, render?, align?, width?, className?, headerClassName?, cellClassName?, hidden?, sticky?, summary?, onCellClick?, href? }`. `key` doubles as the accessor into the row when `render` is omitted (`null`/`''` → `-`, booleans → `Sí/No`). `render` is the escape hatch for badges, currency, colour circles, etc. `hidden` drops a conditional column (e.g. "Sucursal" only when the active branch is `0`). `cellClassName(row, index)` highlights individual cells (missing data, alerts). `sticky` pins the column to the left during horizontal scroll. `summary` fills a totals row rendered right under the header — it only exists when at least one column defines it, and it stays sticky under the header too. `footer` does the same at the bottom of the table (`<tfoot>`), for per-column totals after the rows.
    - `data: T[]`, `getRowKey?` (defaults to `row.id`, falls back to the index).
    - **Columns can be built dynamically** — a matrix table (rows = branches, one column per model) is just a `columns` array derived from the data in the consuming component. The table never fetches or reshapes data itself.
    - **Cell-level actions:** `onCellClick(row, index)` renders that cell underlined and clickable (the "click the id → open a modal" pattern); `href(row, index)` does the same but navigates with `next/link`.
    - **Row actions:** `actions: GenericTableAction<T>[]` — `{ label, onClick?, href?, icon?, showLabel?, variant?, hidden?, disabled?, className? }`. `label` also accepts `(row, index) => string` for a button that toggles its own text (`Previsualizar` / `Ocultar`). Text-only by default; passing `icon` (a shorthand — `'edit' | 'view' | 'delete' | 'download' | 'upload' | 'add' | 'print' | 'copy' | 'send' | 'document' | 'link' | 'check' | 'close' | 'more'` — or any `lucide-react` component) switches it to an icon button that shows `label` as a hover tooltip; `showLabel` renders icon + text. `href` navigates, `onClick` calls back. Header/alignment via `actionsHeader` (default `Acciones`) and `actionsAlign` (default `right`).
    - **Layout/state:** `title`, `toolbar` (right side of the title bar — table-level extras such as an "Actualizando..." hint; **filters and search bars stay outside the table**, in the consuming component, so a re-render of the table never unmounts them), `footer` (the `ExportButton` lives here), `caption`, `isLoading` + `skeletonRows`, `emptyMessage`, `onRowClick`, `rowClassName`, `striped` (default `true`), `density` (`comfortable` | `compact`), `headerVariant` (`muted` | `transparent`), `stickyHeader` (default `true`, which caps the body at `70vh` so the header really stays pinned — short tables never reach the cap), `maxHeight` (explicit cap, e.g. `'60vh'`), `pagination`, `className`, `tableClassName`.
    - **Pagination:** `pagination: { currentPage, totalPages, onPageChange, totalElements?, pageSize?, onPageSizeChange?, pageSizeOptions? }`. Adding `totalElements` + `pageSize` renders the "Mostrando 1-10 de 53" line; adding `onPageSizeChange` renders the records-per-page select (defaults `[10, 20, 50]`). The pager itself only appears with more than one page.
  - **Implementation notes:** it renders its own `<table>` (the `Table` atom hardcodes an `overflow-auto` wrapper that would break sticky headers on page scroll) but reuses `TableHeader/Body/Row/Head/Cell`. `border-separate` is required for sticky header borders, so row separators live on the cells, not on `<tr>`. Every row declares an opaque background because a pinned column inherits it (`bg-inherit`) to stay opaque while scrolling. The scroll container carries a slim custom scrollbar (`SCROLLBAR_CLASS`: `scrollbar-*` for Firefox, `::-webkit-scrollbar` arbitrary variants for the rest). **Its whole stacking scale (`z-[1]`…`z-[4]`) stays below the `z-30` of the sticky island navbar** (it was written against the old `MenuLayout` `<aside>`, `z-10`). Never use `bg-muted` here: `--muted` is `#000000` in `globals.css`.
- **`RevertMovementDialog`** (`components/modals/RevertMovementDialog.component.tsx`)
  - Confirmación del revert de administrador, compartida por las dos fichas. Props: `{ open, onOpenChange, target: 'order' | 'transaction', id, summary?, onReverted? }`.
  - **Dónde aparece el botón, y por qué ahí:** en `TransactionDetailsDialog` solo si la transacción **no** tiene `orderNumber` (un movimiento suelto: traslado, compra a Empire, venta a Arranca); en `OrderDetailsModal` si la orden existe y no está `canceled`. Una línea que pertenece a una orden se revierte desde la orden, para que sus totales y métodos de pago se vayan con ella — el backend lo rechaza con 409 igual, así que la ubicación del botón es la comodidad, no la garantía.
  - `onReverted` cierra la ficha: la fila desaparece de todas las listas al revertirse (`Transaction.objects` está filtrado en el backend), así que la ficha abierta ya no describe nada.
  - **In use:** `BikeInventorySection` (clickable id → `BikeDetailsModal`, conditional "Sucursal" column), `GeneralBikeInventorySection` (colour circles), `AdminBikeInventorySection` (branches × models matrix with a pinned first column and a totals row), `PartInventorySection` (clickable id → `PartInventoryBranchModal`, "Costo" column only for `admin`), `GlobalPartInventorySection` (one column per branch, built from `useAllBranches`), `UserList`, `OrdersTable`, `DeliveryNotesTable` (two conditional row actions), `UsedBikesTable` (`onRowClick` + badges + responsive columns via `hidden md:table-cell` on `className` **and** `headerClassName`), the bikes-history page, and every report: `SalesReport` (vehicles + spares), `DailyReport` (its seven tables, two of them with `footer` totals), `MechanicsReportTable`, `SellersReportTable` (two different cell-click targets in the same row) and `PartsReportTable` (both tabs); plus `TransactionList` (columns that are empty in every row are dropped with `hidden`), shared by the bikes/parts/services transaction views, `TopPartsTable`, `BranchTable` (click the name → per-branch inventory dialog), `TotalDebtTable` and `DebtObjectsTable` (both with a `footer` total), the three tables of the surveys module — `SurveysTable`, `VersionsPanel` (its preview action toggles its own label) and `ResponsesTable` — `ClientsTable`, `GpsTabbedTable` (las dos tablas del monitoreo de GPS, con paginación de cliente sobre un snapshot ya en memoria), `ArrancaBalanceReport` (paginación de servidor, pestañas por estado), and the order's `TransactionsTable` (inside `OrderDetailsModal`; clicking the id opens `TransactionDetailsDialog` **on top of** the order modal — Radix stacks the layers, and closing the inner one only clears its own id, so the order modal is still there underneath).
  - **`AdminBikeInventorySection` y "Ver por recibir de Empire":** con el interruptor prendido la sección llama `generalBikeInventory.setPending(true)` (`useBranchInventory`) y el inventario general se pide con `pending=true`: el backend agrega las sucursales y los modelos que hoy están en 0 pero tienen motos por recibir, así cada "+N" tiene su fila y su columna. Se hace en el backend y no mezclando `pendingMatrix` en el cliente porque la matriz está paginada por sucursal: una sucursal con stock en la página 2 aparecería repetida en la 1. Una celda en 0 se pinta como "no la tiene" (`bg-red-50`, guion) con el "+N" debajo.

## Services

Every service instantiates `MotoCandelaHttpService` and passes the auth token per call. Domain response types live in `services/<domain>/types/`.

- **`MotoCandelaHttpService`** (`services/motoCandelaHttp.service.ts`)
  - **Purpose:** Axios wrapper. Base URL from `NEXT_PUBLIC_API_URL` (fallback `http://localhost:8000/api`), injects `Authorization: Token <token>`, handles custom `Content-Type` (multipart).
  - **Key methods:** `get()`, `post()`, `put()`, `patch()`, `delete()`
  - **Errors:** every failed request is also stored in `apiErrors/recentApiErrors.store` (the last 5: endpoint, method, status, envelope `message` and the **payload** sent — `params` for a GET, `data` otherwise; never headers or the token) so a support report can attach them. In the payload, keys matching `pass|token|secret|authorization` are replaced by `[oculto]`, files become `{ file, type, size }`, `FormData` becomes an object, and anything over 5 000 chars is stored as `{ truncated, preview }`. Errors from `/support/*` are skipped so they don't hide the ones being reported. The error is still re-thrown unchanged. Calls that bypass this service (direct `axios`/`fetch`) are not captured.
- **`AuthService`** (`services/auth/auth.service.ts`)
  - **Purpose:** Session and current-user resolution.
  - **Key methods:** `login()`, `logout()`, `getCurrentUser()`, `getUserById()`, `getUsers()`, `getAllUserBySearch()`
- **`ProductsService`** (`services/products/products.service.ts`)
  - **Purpose:** Products, inventories, categories, prices and the USD/USDT rate.
  - **Key methods:** `getAllBikes()`, `getAllParts()`, `getProductBySku()`, `getById()`, `getAllCategories()`, `getBikeInventory()`, `getGeneralBikeInventory()`, `getGlobalPartInventory()`, `getPartInventory()`, `getAllBikesHistory()`, `getOtherProducts()`, `getFinancialProducts()`, `getSoldProducts()`, `getPurchasedProducts()`, `getNoCostProducts()`, `getBikeInventorySummary()`, `getPartInventorySummary()`, `getTopParts()`, `createProduct()`, `patchProduct()`, `deleteProduct()`, `postImage()`, `uploadPartInventoryExcel()`, `bulkUpdateBikePrices()`, `bulkUpdatePartPrices()`, `getExchangeRate()`, `updateUsdtRate()`
  - **Bulk lookup by id/sku** (`POST /products/byids`, types in `types/ProductsByIds.type.ts`): `getProductsByIds(token, ids, skus = [])`. A **POST that reads nothing** — the lists go in the body to dodge URL length limits. Unpaginated, and `ids` and `skus` can't both be empty (a 400). Unknown ids/skus are **not a 404**: they come back in `data.missingIds` / `data.missingSkus` with a `200`, so check them before rendering; a product matched by both id and sku comes back once. `products` is in database order, **not** the order you asked for — key by `id`, never by array position.
  - **Used bikes** (`/products/usedbikes`, types in `types/UsedBike.type.ts`): `getUsedBikesTable()` (branch `0` = all), `getUsedBikeById()`, `createUsedBike()`, `updateUsedBike()`, `deleteUsedBike()`.
    - Related fields (`product`, `owner`, `reviewer`, `responsible`, `branch`) are **ids on write and nested objects on read**; `surveyResponse` is an id both ways.
    - `reviewer` and `responsible` are two different people: `reviewer` is the **mechanic** picked in `UsedBikeForm` when the unit is registered (only an admin may reassign it afterwards), `responsible` is whoever **takes the evaluation** from the sheet (set on "Comenzar evaluación", cleared on resign).
    - `notes` is free text. The approval flow writes the agreed **payment method** there with a PATCH **before** calling the approve endpoint (which doesn't accept it); if none was picked the PATCH is skipped rather than sending `null`, which would wipe whatever was noted.
    - `cost` is PATCHed from the price scale as soon as the offer is confirmed, ahead of any decision — so a negotiation left half-done is not lost. Clearing the field writes `null` on purpose.
    - `productPrices` is a JSON column **replaced wholesale on PATCH** — always send the full array. Each entry is `{ productId, quantity, price, questionId }` and nothing else: `price` is per unit and `questionId` is the survey question (`answers[].question.id`) the part repairs. **Only the product id is stored** — to render names on reopen, resolve them with `getProductsByIds()`.
    - `DELETE` is a hard delete, and `status` transitions are not validated server-side.
  - **Approval** (`POST /products/usedbikes/<id>/approve[/<branchId>]`): `approveUsedBike()`. Body is `{ cost?, margin?, in_number? }` — `margin` is a percentage with up to two decimals (`18.18`) that the front **derives** from the price scale rather than asking for — there is no UI to pick one — and omits when it falls outside `[0, 100)`, in which case the backend applies its own. `cost` falls back to the stored one; `in_number` is the purchase transaction's entry number and is **snake_case**, unlike the rest of the API (it reads back as `inNumber`). Atomically writes `cost`, derives `price = cost / (1 - margin/100)` (margin is a share of the **selling** price, so it grosses up — the opposite direction to the pricing calculator), creates the purchase transaction (from supplier branch 11, `used: true`, `amount` = cost), links it as `purchaseTransaction` and sets `status` to `approved` — **don't PATCH cost, price or status separately**. `margin` itself is not stored. Re-approval is blocked by the `purchaseTransaction` FK, and it **is not reversible through the API**.
  - **Used-bike pricing** (`POST /products/usedbikes/pricing/<case>`, types in `types/UsedBikePricing.type.ts`): `calculateUsedBikePricing()`. Pure calculation, persists nothing.
    - `case` 1 = by condition (survey score scales market value), 2 = by repairs (parts cost subtracted), 3 = both side by side. The UI always asks for 3.
    - Percentages are **whole numbers** (`20`, not `0.20`), and `products[].price` is **per-unit**. `margin` is optional and the UI does **not** send it here — the calculator gets no margin; the front derives one from the result and only uses it at approval time.
    - Returns a buy range for `cost`: `minPrice` is the opening offer (full margin), `maxPrice` the ceiling (reduced margin). If `case2.netBase <= 0` the order inverts — check before rendering a range.

## Global State and Contexts

**There are no hand-written React Contexts for domain state** (only the internal contexts of `Form` and `Toast`). Two layers:

### Server state — TanStack React Query v4

- `Providers` (`components/providers/providers.component.tsx`) creates the `QueryClient`, mounts `ReactQueryDevtools`, and calls `initializeBranchId()` on mount.
- Cache presets per domain (`PRODUCTS`, `USERS`, `TRANSACTIONS`, `INVENTORY`, `BRANCHES`, `DEFAULT`) live in `config/queryOptimization.config.ts` and are applied through `applyQueryConfig()`.
- The `QueryClient` is created with no `defaultOptions`, so React Query's defaults apply (`refetchOnWindowFocus: true`, `staleTime: 0`): coming back to the tab refires every mounted query. The `INVENTORY` preset turns that off (`refetchOnWindowFocus: false`, `staleTime` 30s) and `useBranchInventory` / `useGlobalPartInventory` / `useAllBikes` / `useAllParts` spread it in; `BRANCHES` does the same for the branch list. **Any new paginated table query should do the same** — otherwise switching windows re-downloads whole inventories nobody asked for.
- Query keys are conventionally `[domain, token, params]`.

### Client state — Zustand v4 (`src/stores/`)

Each store exposes **atomic selector hooks** plus a single `actions` object (stable reference), and imperative getters for use outside React.

- **`auth.store.ts`** — session: `user`, `token`, `isLoggedIn`, `authService`.
  - Hooks: `useUser`, `useToken`, `useIsLoggedIn`, `useUserRole`, `useRoles`, `useIsStaff`, `useSuperuser`, `useIsSuperAdmin` (non-staff superuser or `admin` role, same rule as the backend's `is_super_admin`), `useIsManagerView` (Super Admin, `manager` or `administrator`: who gets the manager home), `useSeller`, `useAuthService`, `useAuthActions`
  - Imperative: `loginUser()`, `logoutUser()`, `getToken()`, `getActions()` (also syncs the `token` cookie / `TOKEN` in localStorage read by the middleware and the route guard).
- **`branch.store.ts`** — active branch: `currentBranchId`, `currentBranchType`, `branches`, `isLoading`.
  - Hooks: `useCurrentBranchId`, `useCurrentBranchType`, `useBranches`, `useIsLoadingBranches`, `useBranchActions`
  - Imperative: `initializeBranchId()` (cookie hydration), `setBranchFromUser()`, `getCurrentBranchId()`
- **`order.store.ts`** — order builder cart: `selectedBikes`, `selectedParts`, `selectedOthers`, `orderPayments`, `orderTotalPayment`, `orderDetails` (types `SelectedBike`, `SelectedPart`, `SelectedOtherProduct`, `PaymentMethod`, `OrderPayment`, `OrderTotalPayment`).
- **`usedBikeEvaluation.store.ts`** — used-bike intake wizard: `usedBikeId`, `answers`, `issues` with assigned repair products, and the questionnaire `score` (`AssignedProduct`, `EvaluationIssue`, `EvaluationScore`). `AssignedProduct.price` is the **unit** price and `quantity` the number of units; line totals are `price * quantity`.

  - Hooks: `useEvaluationAnswers`, `useEvaluationIssues`, `useEvaluationScore`, `useEvaluationActions`

### Route protection

- `src/middleware.ts` (Edge): redirects `/dashboard/*` to `/?next=<ruta>` when the `token` cookie is missing. There is no `/login` page: the only sign-in is the modal in `LandingNavBar`, which opens itself when `next` is present and returns the user to that route after login.
- **`LandingNavBar` y `LandingFooter`** también se usan en las Páginas. La barra, si la sección no existe en la página actual, navega a `/#sección`, y en la landing hace scroll a `location.hash` al cargar (reintenta ~3 s mientras cargan los catálogos). El pie acepta `sectionBase` y `responsive: 'viewport' | 'container'`.
- **Rutas públicas** fuera de `/dashboard`: la landing (`/`) y las Páginas (`/p/[slug]`, server component con `dynamic = 'force-dynamic'`, `not-found.tsx` propio y `opengraph-image.tsx` que genera la tarjeta para compartir; `NEXT_PUBLIC_SITE_URL` opcional fija `metadataBase`).
- `RoutesProtectionProvider` (client): re-validates the session against `getCurrentUser()` and hydrates the auth store. On an invalid/expired session it clears `TOKEN` + cookies (`logoutUser()`) and redirects to `/?next=<ruta>`.

## Architectural Conventions

1. **Pages are thin; features live in `components/`.** Files under `src/app/**` only compose layout, metadata and a feature component. Business logic never goes in a route file.
2. **Never duplicate base UI.** Anything visual starts from `components/ui/`; extend via `className` + `cn()` and CVA variants instead of creating a parallel primitive. Domain-specific composites go in `components/tables|modals|forms|<domain>/`.
3. **Separate view from data with hooks and services.** Components never call Axios or instantiate a service directly for fetching — they consume a hook in `src/hooks/`, which wraps a service in `src/services/`, which calls `MotoCandelaHttpService`. Every request goes through that wrapper so auth and the base URL stay centralised.
4. **Server state = React Query, client state = Zustand.** Never mirror API data inside a Zustand store. Read the token with `useToken()` and the active branch with `useCurrentBranchId()`; consume stores through their atomic selector hooks, not the whole store object.
5. **Forms = react-hook-form + Zod.** Every form defines its schema in `src/schemas/*.schema.ts`, wires it with `zodResolver`, and renders through the `Form`/`FormField` primitives. Shared response and domain types belong in `services/<domain>/types/` or `src/models/`.

### Naming

- Components: `PascalCase` export in a `camelCase|PascalCase.component.tsx` file.
- Services: `<domain>.service.ts` exporting a `class`. Hooks: `useThing.ts`. Schemas: `thing.schema.ts`. Models: `thing.model.ts`.
- Imports always use the `@/` alias; external packages first, then internal.

### Known debt (avoid propagating)

- `components/ui/button.tsx` duplicates `button.component.tsx`; `hooks/useCarouselImages copy.ts` duplicates `useCarouselImages.ts`; `schemas/modifyUser,schema.ts` has a typo in its filename.
- Two overlapping user services exist (`services/user` and `services/users`) — prefer `UsersService` for listings/roles and `UserService` for create/modify.
